# momobom 최종 인수인계 및 재현 기록

## 버전과 기록 범위

momobom은 제공 케셰브 시작 틀을 바탕으로 학생 화면을 구현한 보안 Agent 학습 프로젝트입니다. 현재 버전은 **검증 중**입니다. 외부 시스템의 실제 연결·집행까지 완료된 제품이나 운영 인증을 받은 v1.0으로 표시하지 않습니다.

| 항목 | 값 |
|---|---|
| 저장소 | https://github.com/momoorr/choi-bujang-secret-vault |
| 작업 브랜치 | `main` |
| 이번에 별도 폴더에서 실행한 기준 커밋 | `a9ff469320c466e58278bc418d55578f7ec02fb6` |
| 기준 커밋 내용 | 21단계 학생 실행 설명서와 이전 단계 누적 코드 |
| 시작 틀 버전 | `on-client/package.json`의 `0.2.21` |
| 실제 확인한 런타임 | Node.js `v24.21.0`, npm `11.19.0` |
| 제공 기준과 차이 | `package.json`의 Node.js 기준은 `24.19.0`. 실행 도구는 실제 버전과 기준 차이를 안내한 뒤 실행했습니다. |
| 실제 확인한 환경 | 학생의 Windows PC, PowerShell, 웹 브라우저. Windows 세부 버전·PowerShell 버전은 이번 기록에서 수집하지 않았습니다. |
| 재현 후 상태 기록 시각 | **2026-10-30 20:36:03 +09:00** |

이 문서를 추가하여 커밋하면 제출 커밋은 위 기준 커밋과 달라집니다. 위 해시를 22단계 최종 제출 해시로 재사용하지 않습니다. **최종 제출 해시는 문서 추가 후 실제 생성된 커밋의 `git rev-parse HEAD` 출력으로 확정하며, 그 커밋을 별도 폴더에서 다시 확인합니다.** 문서 작성 시점에는 그 최종 커밋의 재현 결과를 확인하지 않았습니다.

기존 실행 설명서는 [STUDENT_RUNBOOK.md](STUDENT_RUNBOOK.md), 제공 실행 안내는 [STUDENT_LAUNCH_GUIDE.md](STUDENT_LAUNCH_GUIDE.md)입니다. 기존 설명서의 사용자별 절대경로는 그 PC의 작업 위치 기록입니다. 다른 PC에서 같은 절대경로를 만들 필요는 없으며, 아래 절차는 저장소 기준 상대경로를 사용합니다.

위 절차의 개별 실행 시각은 따로 수집하지 않았습니다. 표의 결과는 2026-10-30에 수행한 기준 커밋의 기록이며, 최종 제출 커밋 전체의 실행 성공으로 확대하지 않습니다. Git 상태 확인은 무시된 개인 설정이나 원격 데이터베이스의 내용까지 검사한 결과가 아닙니다.

이번 실행은 `-Demo`를 붙이지 않은 기본 실행입니다. **기본 화면이 보인 사실은 접근 제어·XDR·AI 게이트웨이 연결 성공을 뜻하지 않습니다.** `계정 연결 준비가 끝났습니다` 역시 로그인 승인이나 AI 앱 승인 완료를 뜻하지 않습니다. 기존 폴더의 인증·설정 파일을 복제본에 복사하는 절차는 수행하지 않았습니다.

## 이동 가능한 실행 절차

### 필요한 파일과 프로그램

Git, Node.js, Windows PowerShell, 웹 브라우저를 준비합니다. 제공 실행 안내의 Node.js 범위는 22~24이며 수업 기준은 24.19.0입니다. 이번 학생 PC의 실행 확인은 24.21.0에 한합니다. 다른 OS·다른 PC에서의 실제 재현은 미확인입니다.

| 저장소 기준 경로 | 용도와 보존 범위 |
|---|---|
| `on-client/package.json` | 앱 버전·Node.js 기준·실행 명령. 저장소 최상위의 이전 프로젝트 `package.json`과 구분합니다. |
| `on-client/src/`, `public/`, `tools/`, `vendor/`, `examples/` | 제공 런타임·브라우저 화면·실행 도구와 필요한 누적 파일. 폴더 전체를 Git 커밋 기준으로 받습니다. |
| `on-client/student/` | 학생 구현. 현재 렌더링 함수는 `extension.mjs`에 있습니다. |
| `on-client/docs/` | 제공 문서·학생 실행 설명서·이 인수인계 기록 |
| 저장소 최상위의 이전 단계 파일 | 누적 작업으로 보존합니다. 이번 앱을 실행하려고 이전 웹 프로젝트를 다시 배포하거나 의존성을 변경하지 않습니다. |

이 커밋의 `on-client`에는 `package-lock.json`과 `.env.example`이 없습니다. 저장소 최상위의 `package-lock.json`을 앱 폴더로 복사하지 않습니다. 제공 README에 `.env.example` 언급이 있지만 실제 추적 파일에는 없으므로, 없는 견본을 채우거나 비밀 설정을 새로 만들라는 절차를 추가하지 않습니다. 현재 앱은 외부 npm 의존성이 없어 `npm install`이나 `npm ci` 없이 실행했습니다.

기본 실행 도구는 프로젝트 밖 Windows 사용자 영역에 프로젝트별 계정 연결 설정을 준비합니다. 프로젝트 위치가 달라지면 별도 프로젝트로 취급되므로 기존 자격 보관소를 무작정 옮기지 않습니다. 실제 연결이 필요한 경우에만 공식 화면에서 같은 계정과 확인 번호를 대조하여 다시 승인합니다. SDP 연결 설정·공개 조회 허용 목록·집행 서버는 학생이 임의로 만들거나 변경하지 않습니다.

### 최종 제출 커밋을 받는 절차

아래는 **문서를 커밋하고 push한 뒤 수행할 절차**입니다. 원래 프로젝트 밖에서 PowerShell을 열고, 아직 없는 새 폴더를 사용합니다. 제출할 40자리 해시는 실제 Git 출력에서 확인한 값을 입력합니다. 이 절차를 적었다는 것만으로 실행한 것으로 기록하지 않습니다.

```powershell
& {
    $ErrorActionPreference = 'Stop'
    $stage22Commit = (Read-Host '확인할 최종 제출 커밋 40자리를 입력하세요').Trim()
    if ($stage22Commit -notmatch '^[0-9a-fA-F]{40}$') { throw '40자리 커밋을 확인하세요.' }
    $stage22Destination = Join-Path (Get-Location).Path 'momobom-final-reproduce'
    if (Test-Path -LiteralPath $stage22Destination) { throw '대상 폴더가 이미 있습니다. 보존하고 다른 새 폴더를 사용하세요.' }
    git clone --branch main 'https://github.com/momoorr/choi-bujang-secret-vault.git' $stage22Destination
    if ($LASTEXITCODE -ne 0) { throw '복제에 실패했습니다.' }
    git -C $stage22Destination checkout --detach $stage22Commit
    if ($LASTEXITCODE -ne 0) { throw '제출 커밋을 선택하지 못했습니다.' }
    $stage22Actual = (git -C $stage22Destination rev-parse HEAD).Trim()
    if ($LASTEXITCODE -ne 0 -or $stage22Actual -ne $stage22Commit) { throw '선택한 커밋이 다릅니다.' }
    Write-Output $stage22Actual
    git -C $stage22Destination status --short
    if ($LASTEXITCODE -ne 0) { throw '복제본 상태를 확인하지 못했습니다.' }
    Set-Location (Join-Path $stage22Destination 'on-client')
}
```

커밋이 일치하고 상태를 확인한 뒤 앱 폴더에서 순서대로 실행합니다.

```powershell
node --version
npm.cmd --version
npm.cmd run check
```

문법 검사에 오류가 없으면 실행합니다. `5190` 포트를 쓰던 재현 앱은 먼저 그 실행 창의 `Ctrl+C`로 종료합니다. 포트를 다른 프로그램이 사용한다면 그 프로그램을 임의로 종료하지 말고 사용 가능한 다른 포트와 해당 브라우저 주소를 사용합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -Port 5190
```

정상 시작 안내와 실제 브라우저 `http://127.0.0.1:5190/`의 보호 현황 화면을 각각 확인합니다. 실행 창에서 `Ctrl+C`로 종료한 뒤 같은 명령으로 다시 실행하고 브라우저를 새로고침합니다. 기본 포트는 `5189`이며 이번 재현에서는 기존 앱과 구분하기 위해 제공 도구의 `-Port 5190`을 사용했습니다.

예제가 필요한 경우에만 제공 도구의 `-Demo` 또는 `npm.cmd run demo`를 사용하며, 그 결과에는 반드시 예제라고 표시합니다. 이번 기준 커밋 재현에서는 예제 실행과 실제 AI 요청·보안 조치 요청을 수행하지 않았습니다.

## 누적 기능과 검증 범위

다음 함수들은 기준 커밋의 `on-client/student/extension.mjs`에 포함되어 있음을 원문으로 확인했습니다. 제공 `public/app.js`가 입력 전달·재조회·취소를 처리하고 `src/`가 서버·외부 연결을 담당합니다. 학생 함수는 받은 값을 표시하며 별도의 인증·집행 기능을 추가하지 않습니다. 단계별 세부 확인 시각이 없는 항목은 아래와 같이 미수집 또는 미확인으로 남깁니다.

## 데이터 보존·백업·복원 계획

아래 내용은 **계획**이며 이번 재현에서 백업·복원 명령이나 원격 데이터 복구를 실행하지 않았습니다.

| 보존 대상 | 백업과 복원 방법 | 제한 |
|---|---|---|
| 학생 코드·문서·누적 Git 기록 | 변경 파일과 비밀값을 확인한 뒤 명시한 파일만 커밋하고 해당 커밋을 원격에 보존. 별도 로컬 백업이 필요하면 프로젝트 밖 새 경로에 `git bundle create <새 백업파일> --all`을 사용하고 `git bundle verify <백업파일>`로 확인 | Git은 커밋하지 않은 편집·추적하지 않는 파일·무시된 파일·프로젝트 밖 파일을 포함하지 않음. 위 꺾쇠 부분은 실제 새 경로로 바꿔야 함 |
| Git 백업의 복원 | 원래 폴더를 보존한 채 새 빈 경로로 `git clone <백업파일> <새 복원폴더>` 또는 원격 `git clone` 후 기록한 40자리 커밋을 선택. `rev-parse HEAD`와 상태를 확인하고 위 실행 절차 수행 | 복원 실험은 미실행. Git 백업 검사가 앱 실행이나 원격 데이터 복구를 보장하지 않음 |
| 아직 커밋하지 않은 학생 편집 | 변경 파일 목록을 먼저 확인하고 비밀값이 없는 학생 코드·문서만 별도 비공개 백업 위치에 보관하거나 검토 후 커밋 | 원래 폴더 전체를 공개 ZIP·원문 묶음으로 복사하지 않음. 다른 작업을 삭제하거나 덮어쓰지 않음 |
| 인증·개인 설정 | 프로젝트 밖의 기존 보관소를 그대로 유지. 이동 환경은 제공 실행 도구와 공식 승인 절차로 별도 준비 | `.env`, 인증서, 개인키, 토큰, 계정 연결 설정·자격 보관소를 Git·문서·공개 백업에 넣지 않음. 기존 파일의 무작정 복사로 복구하지 않음 |
| 원격 보안 기록·기존 단계의 DB 데이터 | 데이터 원본을 관리하는 시스템의 담당자에게 권한 있는 백업·보존·복구 절차를 확인. 복구 시 대상과 기준 시각 확인 | 저장소 복제는 원격 DB·XDR 기록의 백업이 아님. 학생 화면만으로 서버 데이터를 복구할 수 없음. 이번에 복구 확인하지 않음 |
| 포털 판정·화면 확인 자료 | 해당 단계·커밋·시각을 구분해 보관. 필요한 화면은 비밀값·개인정보를 제외해 저장 | 화면 캡처는 실제 외부 연결이나 실행 효과의 자동 인증이 아님 |

기존 작업으로 돌아가야 하면 원래 폴더를 그대로 사용하고 새 복제본은 진단용으로 보존합니다. 복원 때문에 기존 작업 폴더를 덮어쓰거나 Git 기록을 강제로 되돌리지 않습니다. 서버가 이미 받은 조치의 효과는 Git 복원이나 「조치 화면 취소」로 되돌릴 수 없습니다.

## 미해결 사항과 인수인계 시 확인할 것

| 항목 | 현재 상태와 다음 작업 |
|---|---|
| 최종 제출 커밋 | 이 문서를 포함하여 생성한 실제 해시 확인 → 그 커밋의 새 복제본에서 위 순서 재확인. 확인 전에는 기준 커밋의 결과만 기록 |
| 최종 커밋과 기준 커밋의 차이 | `git diff --name-only a9ff469320c466e58278bc418d55578f7ec02fb6 <최종커밋>`으로 확인. 이번 의도된 변경은 이 학생 문서 한 파일이며 다른 변경이 있으면 내용을 먼저 검토 |
| 최종 재확인 기록 | 실제 최종 해시·시각·환경·명령 결과·학생의 브라우저 확인·남은 미확인을 프로젝트 밖 별도 기록으로 보존. 문서를 수정하여 다시 커밋했다면 이전 해시의 결과와 새 해시를 구분 |
| 포트·런타임·시작 실패 | 실행 창의 첫 오류, 앱 폴더 위치와 Node.js 버전부터 확인. 다른 프로그램·보안 설정을 임의로 변경하지 않고 제공 실행 안내에 따라 복구 |
| 외부 시스템 미연결 | 실제 계정·기기·세션·업무 앱 판정·보안 기록은 별도 연동 확인 필요. 연결 없음을 정상·안전·접속 허용으로 바꾸지 않음 |
| AI | Workbench 수업용 AI, 앱 안 AI 설명, 포털 공식 판정 AI는 서로 다른 역할. 모델 목록 응답만으로 사건 설명 성공을 표시하지 않음 |
