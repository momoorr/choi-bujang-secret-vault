# momobom 실행 안내와 완성 기록

momobom은 제공 케셰브 시작 틀의 PC 조회 기능과 학생 비교 화면을 함께 사용하는 학습 앱입니다. 현재 상태는 **검증 중**입니다. 아래에서는 제공 기능·학생 개선, 실제 PC 확인·모의 점검·미확인을 구분합니다.

## 1. 처음 실행하는 사람을 위한 안내

### 준비와 작업 위치

- Windows, Git, Node.js, PowerShell, 웹 브라우저를 준비합니다. 제공 실행 안내의 Node.js 범위는 22~24, 수업 기준은 24.19.0입니다.
- 학생 PC에서 마지막으로 공유된 버전 출력은 Node.js v24.21.0 / npm 11.19.0입니다(2026-10-30). 운영체제 세부 빌드와 PowerShell 버전은 수집하지 않았습니다.
- GitHub 저장소: https://github.com/momoorr/choi-bujang-secret-vault
- 기존 프로젝트를 보존하여 사용하거나, GitHub에서 제출할 커밋을 새 폴더에 받습니다. 이전 프로젝트의 인증·설정 파일을 무작정 복사하지 않습니다.
- **저장소 최상위 폴더**에서 PowerShell을 열고 아래 명령으로 앱 폴더에 들어갑니다. 저장소 최상위의 이전 웹 프로젝트와 실행 위치를 구분합니다.

```powershell
Set-Location .\on-client
node --version
npm.cmd --version
npm.cmd run check
```

현재 `on-client/package.json`에는 외부 npm 의존성이 없으므로 추가 패키지 설치 없이 실행했습니다. 저장소 최상위의 `package-lock.json`을 앱 폴더로 복사하지 않습니다. `check`는 학생 JavaScript의 문법 검사이며 실제 기능 실행 검사가 아닙니다.

### 실행·조회·종료

위 앱 폴더에서 실행합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
```

1. 실행 창에 `케셰브가 켜졌습니다`와 로컬 주소 안내가 나오면 창을 켜 둡니다. 실행 도구의 기본 안내 이름과 브라우저의 학생 앱 이름은 다를 수 있습니다.
2. 브라우저에서 `http://127.0.0.1:5189/`를 엽니다. 상단 앱 이름은 꾸밈이 적용되면 **momobom**입니다.
3. 보호 현황의 제공 **내 PC 상태** 영역에서는 「내 PC 확인」으로 여섯 항목을 조회합니다.
4. 학생 상태·알림 표시의 **PC 자원 비교**에서는 「PC 자원 비교 조회」를 한 번 눌러 기준값을 만듭니다. 두 번째 조회부터 CPU·메모리 사용량과 디스크 여유 공간의 직전 값·최근 값·변화를 확인합니다. 찾기 어렵다면 브라우저 찾기에서 `PC 자원 비교`를 검색합니다.
5. 「계산 기준 보기」를 펼치면 단위·조회 범위·해석 한계를 읽을 수 있습니다. 새로고침하면 비교 기준이 초기화됩니다.
6. 종료는 앱을 실행한 PowerShell 창에서 `Ctrl+C`입니다. 다시 실행하려면 같은 앱 폴더에서 위 실행 명령을 사용합니다.

포트가 이미 사용 중이면 기존 프로그램을 임의로 종료하지 않고 제공 도구에 `-Port 5190`을 붙여 실행할 수 있습니다. 이때 브라우저 주소도 `http://127.0.0.1:5190/`으로 바꿉니다.

기본 실행의 **연결 없음**은 외부 접근 제어·XDR 시스템 상태이며 로컬 PC 실측과 별개입니다. 계정 연결 준비 메시지는 로그인·AI 승인 완료가 아닙니다. 이 안내의 PC 조회와 비교에는 API 키 입력이 필요하지 않습니다.

### 막혔을 때

| 상황 | 확인 순서와 복구 |
|---|---|
| 주소가 열리지 않음 | 앱 실행 창이 켜져 있는지 → 실행 창의 첫 오류 → `on-client` 작업 위치와 실제 안내된 포트 확인 |
| Node.js 기준 버전 안내 | 실제 버전과 제공 실행 안내의 지원 범위를 확인. 기준 버전과 다른 실행 결과를 같은 환경으로 기록하지 않음 |
| 비교 영역의 `NETWORK_ERROR` | 로컬 앱 서버 실행 여부 확인 → 같은 앱 폴더에서 서버 실행 → 기존 브라우저의 비교 조회 버튼을 직접 눌러 재조회 |
| 시간 초과·응답 확인 불가 | 현재 결과는 미확인으로 두고 원인을 확인한 뒤 직접 재조회. 실패 뒤에는 비교 기준을 새로 시작 |
| 일부 항목만 확인 불가 | 해당 카드의 이유를 확인. 읽지 못한 값을 0이나 정상으로 대체하지 않음 |
| 꾸밈이 적용되지 않음 | `student/appearance.json`의 표시된 오류 항목과 파일 저장 상태 확인 → 브라우저 새로고침. 기존 제공 파일을 고쳐 우회하지 않음 |

실제 OS 조회는 제공 `src/pc-status.mjs`가 담당하고, 제공 화면은 `public/pc-status-view.mjs`가 표시합니다. 학생 추가 기능은 `student/extension.mjs`의 `createStudentView`에서 제공 API를 받고 `renderStatus` 안의 비교 영역을 그립니다. 앞 단계의 다른 렌더링 함수와 제공 서버·`public/app.js`·`public/style.css`는 이번 개선에서 수정하지 않았습니다.

`student/appearance.json`에는 앱 이름 **momobom**, 밝은 배경 `#f4f7fb`, 네이비 강조색 `#1e3a5f`, 흰 카드 `#ffffff`, 허용된 `student-first` 배치만 지정했습니다. 상태의 의미를 바꾸는 설정이나 인증·권한 설정은 추가하지 않았습니다.

실제 연결 실패·복구는 표형 화면에서 확인했습니다. 카드 변경에서는 조회·검증·변화 계산 코드를 그대로 보존했으며, 카드형 실패 분기는 모의 입력으로 확인했습니다. 카드형 화면에서 서버 종료 시험을 다시 실행했다고 기록하지 않습니다.

값과 단위는 CPU 사용률 `%`, CPU 차이 `%p`, 메모리 사용량과 디스크 여유 공간 `GiB`로 구분합니다. 확인 불가와 부분 결과를 정상·안전으로 바꾸지 않습니다. 기본 실행과 예제(`-Demo`)도 구분하며 이번 PC 비교 확인은 예제 모드가 아닙니다.

## 4. 시연 순서

1. 제공 **내 PC 상태**에서 자원·네트워크·방화벽·최근 기록을 보여 주고 제공 기능임을 설명합니다.
2. 학생 **PC 자원 비교**에서 두 번 수동 조회하여 출처·측정 시각·변화를 설명합니다. 메모리는 사용량, 디스크는 여유 공간이며 Windows 경고·오류는 침해 판정이 아님을 말합니다.
3. **계산 기준 보기**를 키보드로 펼쳐 단위·수동 조회·초기화·오류 복구 안내를 설명합니다. 실제로 보여 주지 못한 기능은 미확인으로 남깁니다.

## 5. 버전·지원 범위와 다음 인수인계

| 구분 | 식별과 범위 |
|---|---|
| 시작 틀 | `on-client/package.json`의 0.2.21. 학생 앱의 운영 완성 버전 번호를 뜻하지 않음 |
| 22단계 통과 기준 커밋 | `22134c41319b118c069da3896c08be4f03eb4a98`. 포털 통과를 학생이 보고했으며 원문 검토 결과와 실제 운영 인증을 구분 |
| PC 비교 기능 저장점 | `974320e08a71808569ccee83a0e469e6b052c407` |
| 이번 마무리 변경 | 위 저장점 이후의 비교 카드 표시, `student/appearance.json`과 이 학생 문서. 문서 작성 시점에는 새 최종 커밋 미확정 |
| 최종 제출 버전 | 위 변경을 검토·커밋·push한 뒤 Git 최상위의 `git rev-parse HEAD` 출력과 GitHub의 같은 커밋으로 식별. 제출할 40자리 메모가 최종 식별자 |
| 포장 | 이번 과정에서는 하지 않음. 설치 패키지 경로·소스와 패키지 대조는 해당 없음 |

처음 사용하는 다른 사람의 실행을 관찰한 것은 **미실시**입니다. 이전 단계의 별도 폴더 재현은 [STUDENT_HANDOFF.md](STUDENT_HANDOFF.md)를 참고하며, 그 결과를 이번 카드·꾸밈이 포함된 최종 버전의 새 폴더 재현으로 옮겨 적지 않습니다. 이번 최종 커밋의 새 폴더 실행은 문서 작성 시점 **미확인**입니다.

기존 실행 설명서 [STUDENT_RUNBOOK.md](STUDENT_RUNBOOK.md)와 인수인계 기록은 보존합니다. 수정 전 학생 소스 백업은 프로젝트 밖에 남기고 인증·설정·키 파일을 Git에 넣지 않습니다. 원격 보안 기록과 기존 프로젝트의 DB 데이터는 Git 복제로 백업·복원되지 않으며, 보존·복원 계획은 기존 인수인계 문서와 구분해 따릅니다.

이번 PC 기능 개선에는 외부 서비스 가입이나 개인 AI 설정을 추가하지 않았습니다. 실제 접근 제어·XDR 연동, 이 마무리본의 AI 사건 설명·OSV 조회·실제 보안 조치 집행은 미확인입니다. 19단계 실제 집행은 기다림(UNV)이며, 새 화면을 만들었다는 사실로 완료 처리하지 않습니다. 다른 PC·다른 OS, 화면 낭독기·200% 확대·전체 앱 키보드 검수도 미확인입니다.

AI는 코드 검토·구현 초안·모의 점검·문서 작성에 도움을 주었습니다. 학생은 적용 명령을 실행하고 실제 화면과 오류·복구·키보드 동작을 확인했으며, 강조색을 네이비로 선택했습니다. 강사·동료의 별도 첫 사용 관찰 결과는 이 기록에 없습니다.
